--------------------------------------------------------------------------------

Persistence : Session stored to localStorage key 'foamProSession'

6. CORE FEATURE: CALCULATION ENGINE (utils/calculatorHelpers.ts)
--------------------------------------------------------------------------------
Four calculation modes:
  BUILDING    — Full building: walls + pitched roof + optional gables
  WALLS_ONLY  — Linear footage walls only
  FLAT_AREA   — Flat slab/attic (L×W), optional pitch factor
  CUSTOM      — Manual sqft override

Calculation pipeline:
  1.  Parse pitch string (accepts "X/12" notation, degrees, or bare number)
  2.  Compute pitch factor: sqrt(1 + (rise/run)^2)
  3.  Apply metal surface factor (+15% if corrugated metal substrate)
  4.  Calculate wall area (linear_ft × height × 2 sides)
  5.  Calculate gable area (triangular end walls from pitch geometry)
  6.  Calculate roof area (footprint × pitch factor)
  7.  Sum additional areas (walls or roofs added as extra line items)
  8.  Split total area into open-cell (OC) and closed-cell (CC) zones
  9.  Apply waste percentage to each zone
  10. Compute board-feet: area × depth × waste_factor
  11. Divide bdft by yield-per-set → number of sets needed
  12. Multiply sets × strokes-per-set → estimated machine strokes
  13. Material cost: (OC_sets × OC_price) + (CC_sets × CC_price) + inventory_cost
  14. Labor cost: man_hours × hourly_rate + trip_fee + fuel_fee
  15. Pricing modes:
        Cost Plus — material_cost + labor_cost + misc_fees (+ optional margin)
        SqFt      — total_area × $/sqft_rate

Settings configurable per company:
  OC yield (bdft/set), CC yield (bdft/set)
  Strokes per OC set, strokes per CC set
  OC cost per set, CC cost per set
  Labor hourly rate, default waste %

9. DATA PERSISTENCE & SYNC (hooks/useSync.ts + services/api.ts)
--------------------------------------------------------------------------------
Primary store: Supabase PostgreSQL (cloud)
Secondary:     localStorage (offline/backup)

Init load sequence (on session set):
  Parallel fetch:
    → estimates         (filtered by company_id)
    → customers         (filtered by company_id)
    → inventory_items   (filtered by company_id)
    → company_settings  (costs, yields, warehouse counts, lifetime stats)
  Dispatch LOAD_DATA → merges into global state

Auto-save:
  3-second debounce on any appData change
  Saves: company_settings (costs, yields, warehouse foam counts, lifetime usage)
  Local backup: always writes to localStorage key 'foamProState_{username}'

Force refresh:
  forceRefresh() re-fetches all Supabase data and reloads state

Crew polling:
  Crew role skips auto-sync; polls Supabase every 45 seconds via setInterval
  Crew can manually pull latest jobs with a refresh button

Session recovery:
  On app load, reads 'foamProSession' from localStorage
  Validates against Supabase → restores session without re-login

17. SUPABASE EDGE FUNCTION
--------------------------------------------------------------------------------
Function : create-crew-user  (supabase/functions/create-crew-user/index.ts)
Trigger  : HTTP POST from admin in Profile.tsx
Purpose  : Creates a new Supabase Auth user with role='crew' using the
           service-role key (which is not safe to use client-side)
Process  :
  1. Receives email + password + company_id from admin
  2. Uses admin.createUser() with service-role key
  3. Inserts a profiles record with role='crew'
  4. Returns new user id to client

19. KNOWN / NOTABLE PATTERNS
--------------------------------------------------------------------------------
- No URL-based router (React Router not used); all navigation is state-driven
  via UIState.view. Deep-linking is not supported.

- TypeScript strict mode is disabled (tsconfig: "strict": false). Type coverage
  is partial; many components use 'any' implicitly.

- Single context for all global state (no Zustand, Redux, or React Query).
  Large state object may cause unnecessary re-renders on any update.

- Two supabase.ts files exist (services/supabase.ts and src/services/supabase.ts).
  The src/ version appears to be a legacy duplicate; primary is services/supabase.ts.

- backend/Code.js is a Google Apps Script file — fully deprecated and not
  connected to the current app. Can be safely removed.

- Auto-save debounce saves all company_settings on any appData change, even if
  only non-settings fields changed. Minor inefficiency.

- Crew polling uses setInterval(45000) — no exponential backoff or visibility
  API optimization. Will continue polling even when tab is in background.

- PDF logo fetch uses Canvas (drawImage → toDataURL) to bypass CORS on remote
  logo URLs. Fails silently if logo URL is unreachable.
